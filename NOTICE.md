# Third-party content and licensing

This project redistributes and builds on material from two slicers, **both
licensed AGPL-3.0**. That matters here, because AGPL's copyleft reaches network
use: running a modified or derived work as a public web service obliges you to
offer its source to users of that service.

## What is vendored

| Path | Origin | License |
|---|---|---|
| `profiles/bambu_h2c/` | [bambulab/BambuStudio](https://github.com/bambulab/BambuStudio), `resources/profiles/BBL` | AGPL-3.0 |
| `profiles/snapmaker_u1/` | [Snapmaker/OrcaSlicer](https://github.com/Snapmaker/OrcaSlicer), `resources/profiles/Snapmaker` | AGPL-3.0 |
| `profiles/*/config_vocabulary.json` | derived from each project's `src/libslic3r/PrintConfig.cpp` | AGPL-3.0 |

Exact commits are recorded in [`profiles/SOURCES.md`](profiles/SOURCES.md).
The `config_vocabulary.json` files are generated by
[`tools/extract_vocabulary.py`](tools/extract_vocabulary.py), which scrapes
option names, enum values, types and numeric bounds out of that source file —
so they are a derived work of it, not independent data.

Several constants in `convert/` were likewise reverse-engineered from that
source (the `paint_color` bit-packing, the per-extruder-variant array layout).
Those origins are cited in the code where they appear.

## What this means in practice

- **Keep this project's source public** if you host it where others can use it.
  Publishing the repository you deploy from satisfies the obligation; the
  simplest arrangement is a public GitHub repo wired to the host.
- **Keep the attributions.** `SOURCES.md`, this file, and the in-code citations
  are how the upstream projects get credit and how the next maintainer knows
  which files are refreshable and from where.
- **Refresh, don't edit.** Treat `profiles/` as vendored: re-run the extraction
  against a newer upstream commit rather than hand-editing, and update
  `SOURCES.md` to match.

If you would rather not take on the AGPL obligations, run the tool locally —
`cli.py` and `run_web.ps1` involve no distribution at all.

## This project's own code

Everything outside `profiles/` was written for this project. Given that it is a
derived work of AGPL-3.0 software, distributing it under **AGPL-3.0** is the
consistent choice; add a `LICENSE` file saying so before publishing.
